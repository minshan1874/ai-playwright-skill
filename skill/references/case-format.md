# 用例文件格式

`parse-cases.mjs` 支持 `.xlsx`、`.csv` 和 Markdown 表格三种输入。三者共用同一套列定义。

---

## 1. 标准列

| 列名 | 必需 | 说明 |
| --- | --- | --- |
| 用例ID | 否 | 如 `TC-001`。留空时自动编号为 `TC-001`、`TC-002`… 并在 `warnings` 里提示 |
| 模块 | 否 | 如 `登录`、`订单管理`。留空归入「未分类」。报告和计划按模块分组 |
| 用例标题 | **是** | 一句话说明这条用例验证什么 |
| 优先级 | 否 | `P0` / `P1` / `P2` / `P3`。缺失或非法时按 `P2` 处理并告警 |
| 前置条件 | 否 | 执行前需要满足的条件 |
| 操作步骤 | **是** | 用户视角的操作序列 |
| 预期结果 | 否 | 与操作步骤一一对应的预期。缺失时只能验证「不报错」 |
| 测试数据 | 否 | `键=值` 形式，如 `用户名=admin; 密码=123456` |
| 标签 | 否 | 逗号或竖线分隔，如 `smoke, 回归`。会转成 Playwright tag |

### 列名容错

表头识别是宽松的：忽略大小写、空格、全角标点、下划线、括号。以下写法都识别为「操作步骤」：

`操作步骤` / `测试步骤` / `步骤` / `操作过程` / `steps` / `step` / `actions`

其他列同理，完整别名表见 `scripts/lib/cases.mjs` 的 `COLUMN_ALIASES`。
未能识别的列会被忽略，并出现在 `parse-cases.mjs` 返回的 `unknownColumns` 里。

---

## 2. 多值写法

「操作步骤」「预期结果」「前置条件」「标签」都支持一列多值。按以下优先级拆分：

1. **单元格内换行**（推荐）
2. **竖线 `|` 分隔**
3. **行内编号**，如 `1. 打开首页 2. 点击登录 3. 输入账号`

三种写法示例（效果相同）：

```
打开登录页
输入用户名 admin
输入密码 123456
点击登录
```

```
打开登录页 | 输入用户名 admin | 输入密码 123456 | 点击登录
```

```
1. 打开登录页 2. 输入用户名 admin 3. 输入密码 123456 4. 点击登录
```

拆分时会自动去掉行首编号（`1.`、`2、`、`3)`、`4）`）。

### 步骤与预期的对应

- **只写 1 条预期结果**：视为整条用例的总体预期，不做数量校验。这是最常见的写法。
  ```
  操作步骤: 打开登录页|输入账号密码|点击登录
  预期结果: 登录成功并跳转到工作台
  ```
- **写多条预期结果**：与操作步骤按顺序一一对应。数量不一致时**不丢弃**，
  在 `warnings` 里提示并按顺序尽力对应。

如果某一步确实没有独立预期，写成「无变化」而不是留空，避免错位。

## 3. 测试数据

写成 `键=值`，多个用 `;`、`|` 或换行分隔：

```
用户名=admin; 密码=123456; 期望昵称=管理员
```

解析结果是 `{ "用户名": "admin", "密码": "123456", "期望昵称": "管理员" }`，
可在 spec 里通过 `testCase.data` 读取。原始文本同时保留在 `dataRaw` 字段。

没有 `=` 号时不会报错，`data` 为空对象、`dataRaw` 保留原文 —— 适合写自由文本说明。

---

## 4. Excel 相关注意事项

- **多工作表**：默认取第一个有数据的工作表。指定用 `--sheet "<名称>"`。
  可用工作表列表在报错信息里给出。
- **合并单元格**：合并区域内的空白单元格会自动继承左上角的值，所以「模块」列
  纵向合并是安全的。
- **标题横幅**：表头不在第一行也没关系，`parse-cases.mjs` 会扫描前 20 行找表头。
- **重复表头**：中间重复出现的表头行会被跳过并计数。
- **空行**：完全为空的行被跳过，不影响行号引用（`rowRef` 始终是原始行号）。

---

## 5. CSV 相关注意事项

- 分隔符自动识别：逗号、分号、制表符、竖线。取第一行中出现次数最多者。
- 支持 RFC 4180 引号转义（`""` 表示一个引号），字段内可含换行。
- UTF-8 BOM 会被自动去掉。
- **非 UTF-8 编码（如 GBK）不支持**。若中文显示为乱码，请另存为「CSV UTF-8」后重试。

---

## 6. Markdown 表格

适合手写用例或从文档里复制：

```markdown
| 用例ID | 模块 | 用例标题 | 优先级 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- | --- | --- |
| TC-001 | 登录 | 正确账号密码登录成功 | P0 | 打开登录页<br>输入正确账号密码<br>点击登录 | 登录成功并跳转到首页 |
| TC-002 | 登录 | 密码错误提示 | P1 | 打开登录页<br>输入错误密码<br>点击登录 | 停留在登录页<br>提示「密码错误」<br>密码框内容保留 |
```

`<br>` 会被当作换行处理。表格必须至少有表头行和分隔行。

## 7. 解析结果

`parse-cases.mjs --out cases.json` 产出的结构：

```json
{
  "source": "/abs/path/cases.xlsx",
  "format": "xlsx",
  "sheet": "Sheet1",
  "parsedAt": "2025-01-01T00:00:00.000Z",
  "headerRow": 1,
  "columns": { "id": 0, "module": 1, "title": 2, "priority": 3, "steps": 5, "expected": 6 },
  "unknownColumns": [],
  "total": 2,
  "byModule": [{ "module": "登录", "count": 2 }],
  "byPriority": { "P0": 1, "P1": 1 },
  "warnings": [],
  "cases": [
    {
      "id": "TC-001",
      "autoId": false,
      "module": "登录",
      "title": "正确账号密码登录成功",
      "priority": "P0",
      "priorityAssumed": false,
      "preconditions": [],
      "steps": ["打开登录页", "输入正确账号密码", "点击登录"],

      "dataRaw": "",

```

`rowRef` 是原始文件里的行号，报告里用它把失败用例指回 Excel 的具体行。

## 8. 常见报错与处理

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `未能识别用例表头` | 列名完全对不上 | 看报错里列出的期望列名，修正表头，或把表头发给用户确认映射 |
| `表头在第 N 行，但其后没有任何用例数据行` | 只有表头 | 确认数据行紧跟在表头下方 |
| `不支持的用例文件格式` | 扩展名不在支持列表 | 转成 `.xlsx` / `.csv` / `.md` |
| `读取 .xlsx 需要 exceljs 依赖` | 依赖未装 | 运行 `bootstrap.mjs` |
| 中文乱码 | CSV 非 UTF-8 | 另存为 CSV UTF-8 |
| `找不到工作表 "X"` | `--sheet` 写错 | 用报错里给出的可用工作表名 |
